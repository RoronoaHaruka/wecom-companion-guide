# 同幕

> 视频与对话，共处同一秒。
>
> 没眼睛，就装眼睛；没耳朵，就装耳朵。连 Claude 都能无痛看片。

**源码仓库：** <https://github.com/RoronoaHaruka/wecom-companion-guide>

**作者：** Haruka & Roronoa · 2026.09

## 第一章 · 体验先发生

Claude 原本只有文字入口。视频在播放器里向前走时，对话并不知道当前标题、进度和画面。同幕把这条断开的时间接起来：播放页持续发布当前状态与原帧，服务器在画中画或页面挂起后继续沿时间锚续帧，对话入口在新消息抵达时读到同一秒的画面。

视频和聊天可以留在同一块屏幕里。观看者继续播放、切换画中画、向下聊天；Claude 收到的也不再是一张没有前后的静态截图，而是一条带着标题、进度、当前帧和更新时间的连续现场。

> **你问的是这一秒，我回答这一秒。**

公开仓库只提供通用实现与通用界面骨架。真实部署的域名、密钥、内部路径、私人按钮名、家庭产品 UI 与未经公开的访问方式均不进入本教程。

# 第二章 · 从零安装

## 读完以后能得到什么

这份教程组装出一条完整最小链路：`/watch` 固定播放器、原始链接解析、邻近片源预热、同源媒体代理、iPhone 多段 Range、YouTube HLS 重写、播放状态同步、浏览器原帧发布、PiP 后服务器续帧、Claude 当前帧适配，以及一个通用的企业微信「同幕片笺」入口。


### 运行时

- Node.js `20.x` 或更新的 LTS
- ffmpeg `6.x` 或更新版本
- 最新稳定版 yt-dlp
- 一台能访问目标片源的 Linux 或 macOS 主机

- yt-dlp 能解析的普通页面链接
- progressive HTTP 或 HLS 音视频复用格式
- 不包含 DRM，也不绕过站点访问控制
- 需要请求头的片源只保留安全白名单

三条数据始终分开：媒体字节走 stream proxy，轻量播放状态走 sync，当前视觉走一张原子覆盖 JPEG。它们通过同一个 `time` 汇合，任何一条都不需要把完整视频塞进对话。

## 所有外部 URL 都先过 SSRF 边界

```js
function isPrivateIp(value) {
  let ip = String(value || '').toLowerCase().replace(/^\[|\]$/g, '');
  const mapped = ip.match(/^::ffff:(\d+\.\d+\.\d+\.\d+)$/);
  if (mapped) ip = mapped[1];
  if (net.isIPv4(ip)) {
    const [a,b] = ip.split('.').map(Number);
    return a===0 || a===10 || a===127 || (a===100&&b>=64&&b<=127) ||
      (a===169&&b===254) || (a===172&&b>=16&&b<=31) ||
      (a===192&&(b===0||b===168)) || (a===198&&(b===18||b===19||b===51)) ||
      (a===203&&b===0) || a>=224;
  }
  if (net.isIPv6(ip)) return ip==='::' || ip==='::1' || /^f[cd]/.test(ip) ||
    /^fe[89ab]/.test(ip) || /^ff/.test(ip) || /^2001:db8(?::|$)/.test(ip);
  return true;
}

async function assertSafeHttpUrl(raw) {
  let url;
  try { url = new URL(String(raw || '')); } catch { throw new Error('invalid URL'); }
  if (!['http:','https:'].includes(url.protocol)) throw new Error('only http(s) URLs are allowed');
  if (url.username || url.password) throw new Error('URL credentials are not allowed');
  if (url.hostname==='localhost' || url.hostname.endsWith('.localhost') || url.hostname.endsWith('.local') || url.hostname.endsWith('.internal') || net.isIP(url.hostname) && isPrivateIp(url.hostname)) throw new Error('private URL is not allowed');
  const answers = await dns.lookup(url.hostname, { all: true, verbatim: true });
  if (!answers.length || answers.some(x => isPrivateIp(x.address))) throw new Error('URL resolves to a private address');
  return url;
}

async function fetchSafeUrl(raw, options = {}, maxRedirects = 5) {
  let current = (await assertSafeHttpUrl(raw)).toString();
  for (let n=0; n<=maxRedirects; n++) {
    const response = await fetch(current, { ...options, redirect: 'manual' });
    if (![301,302,303,307,308].includes(response.status)) return response;
    if (n===maxRedirects) throw new Error('too many redirects');
    const location = response.headers.get('location');
    if (!location) throw new Error('redirect missing location');
    try { await response.body?.cancel(); } catch {}
    current = (await assertSafeHttpUrl(new URL(location, current))).toString();
  }
}
```

# 第五章 · 完整解析路径

解析器先从分享口令中抽 URL，再让 yt-dlp 只返回单条、已复用音视频的格式。YouTube 把 HLS 放在 progressive format 18 前面。

```js
const FORMAT_DEFAULT =
  'best[ext=mp4][vcodec!=none][acodec!=none][protocol^=http]/' +
  'best[vcodec!=none][acodec!=none][protocol*=m3u8]/' +
  'best[vcodec!=none][acodec!=none]/best';
const FORMAT_YOUTUBE =
  'best[vcodec!=none][acodec!=none][protocol*=m3u8]/' +
  'best[ext=mp4][vcodec!=none][acodec!=none][protocol^=http]/' +
  'best[vcodec!=none][acodec!=none]/best';

function extractUrl(text) {
  if (typeof text !== 'string') return text;
  const match = text.match(/https?:\/\/[^\s，。！？、）)】「」"']+/);
  return match ? match[0] : text.trim();
}

function runYtDlp(url, format) {
  return new Promise((resolve, reject) => {
    const args = [
      '--dump-json', '--no-download', '--no-warnings', '--no-playlist',
      '-f', format, url
    ];
    execFile(YTDLP_BIN, args, { timeout: 30_000, maxBuffer: 5*1024*1024 },
      (error, stdout, stderr) => {
        if (error) {
          const line = String(stderr || '').split('\n').find(x => x.startsWith('ERROR'));
          return reject(new Error((line || error.message).slice(0, 240)));
        }
        try { resolve(JSON.parse(stdout)); }
        catch { reject(new Error('yt-dlp returned invalid JSON')); }
      });
  });
}

function cacheableHeaders(headers = {}) {
  const safe = {};
  for (const [name,value] of Object.entries(headers)) {
    if (/^(user-agent|referer|origin|accept-language)$/i.test(name) && typeof value === 'string') safe[name] = value;
  }
  return safe;
}

function buildVideoResult(info, originalUrl) {
  const directUrl = info.url || info.webpage_url || originalUrl;
  const isHls = String(info.protocol || '').includes('m3u8') || directUrl.includes('.m3u8');
  const result = {
    id: info.id || crypto.createHash('sha256').update(originalUrl).digest('hex').slice(0,12),
    title: info.title || info.fulltitle || 'Untitled',
    thumbnail: info.thumbnail || info.thumbnails?.[0]?.url || null,
    duration: Number(info.duration) || 0,
    url: info.url ? registerVideoStream(directUrl, info.http_headers || {}, isHls ? 'manifest' : 'media') : directUrl,
    ext: info.ext || (isHls ? 'm3u8' : 'mp4'),
    platform: info.extractor || info.extractor_key || 'unknown',
    width: Number(info.width) || 0,
    height: Number(info.height) || 0,
    originalUrl
  };
  Object.defineProperty(result, '_cacheSource', {
    value: { url: directUrl, headers: cacheableHeaders(info.http_headers), isHls },
    enumerable: false
  });
  return result;
}

async function resolveVideoUrl(rawInput) {
  const originalUrl = (await assertSafeHttpUrl(extractUrl(rawInput))).toString();
  const isYouTube = /(?:youtube\.com|youtu\.be)/i.test(originalUrl);
  const info = await runYtDlp(originalUrl, isYouTube ? FORMAT_YOUTUBE : FORMAT_DEFAULT);
  await assertSafeHttpUrl(info.url || info.webpage_url || originalUrl);
  return buildVideoResult(info, originalUrl);
}
```

统一对象让页面、卡片、缓存与 follower 只认一套字段。`url` 是播放器消费的同源地址，`originalUrl` 永远保留最初页面链接。不要把 yt-dlp 的完整 JSON 直接送到前端。

# 第六章 · 去重、缓存与强制刷新

```js
const videoCache = new Map();
const resolveInflight = new Map();

function persistCache() {
  const now = Date.now(), entries = [];
  for (const [url, entry] of videoCache) {
    if (!entry?.data?._cacheSource || now-entry.ts >= CACHE_TTL) continue;
    const x = entry.data;
    entries.push([url, {
      ts: entry.ts,
      data: {
        id:x.id, title:x.title, thumbnail:x.thumbnail, duration:x.duration,
        ext:x.ext, platform:x.platform, width:x.width, height:x.height,
        originalUrl:x.originalUrl
      },
      source: x._cacheSource
    }]);
  }
  const tmp = `${CACHE_FILE}.tmp-${process.pid}`;
  writeFileSync(tmp, JSON.stringify({ entries: entries.slice(-100) }), { mode:0o600 });
  renameSync(tmp, CACHE_FILE);
}

function remember(url, data, ts = Date.now()) {
  videoCache.set(url, { data, ts });
  persistCache();
  return data;
}

function restoreCache() {
  if (!existsSync(CACHE_FILE)) return;
  try {
    const saved = JSON.parse(readFileSync(CACHE_FILE, 'utf8'));
    for (const [url, entry] of saved.entries || []) {
      if (!entry?.source?.url || Date.now()-Number(entry.ts||0) >= CACHE_TTL) continue;
      const data = buildVideoResult({
        ...entry.data,
        url: entry.source.url,
        http_headers: entry.source.headers || {},
        protocol: entry.source.isHls ? 'm3u8' : 'https',
        extractor: entry.data.platform
      }, entry.data.originalUrl);
      videoCache.set(url, { data, ts:Number(entry.ts) });
    }
  } catch (error) { console.error('cache restore:', error.message); }
}
restoreCache();

async function resolveCachedVideo(url, { force=false } = {}) {
  if (force) {
    videoCache.delete(url);
    persistCache();
  } else {
    const cached = videoCache.get(url);
    if (cached && Date.now()-cached.ts < CACHE_TTL) return cached.data;
    if (resolveInflight.has(url)) return resolveInflight.get(url);
  }
  const pending = resolveVideoUrl(url).then(data => remember(url, data));
  resolveInflight.set(url, pending);
  try { return await pending; }
  finally { if (resolveInflight.get(url)===pending) resolveInflight.delete(url); }
}

app.post('/api/video/resolve', auth, async (req, res) => {
  const { url, force } = req.body || {};
  if (!url) return res.status(400).json({ error:'Missing url' });
  try { res.json(await resolveCachedVideo(url, { force:Boolean(force) })); }
  catch (error) { res.status(400).json({ error:error.message || 'resolve failed' }); }
});

app.post('/api/video/batch-resolve', auth, async (req, res) => {
  const urls = Array.isArray(req.body?.urls) ? req.body.urls.slice(0,5) : [];
  if (!urls.length) return res.status(400).json({ error:'Missing urls array' });
  const results = {};
  await Promise.allSettled(urls.map(async url => {
    try { results[url] = await resolveCachedVideo(url); }
    catch { results[url] = null; }
  }));
  res.json({ results });
});
```

同一个 URL 同时被页面、预热和 follower 请求时，只跑一个 yt-dlp。`force:true` 清掉旧解析并生成新 stream key，适合播放器遇到短期地址失效后原地续播。磁盘只落 `_cacheSource` 的安全头，进程内 key 每次启动重建。

# 第七章 · 同源媒体代理与 HLS

```js
const streamKeys = new Map();

function registerVideoStream(url, headers = {}, kind = 'media') {
  const key = crypto.randomBytes(24).toString('hex');
  streamKeys.set(key, { url, headers, kind, ts:Date.now() });
  for (const [k,v] of streamKeys) if (Date.now()-v.ts > STREAM_TTL) streamKeys.delete(k);
  return `/api/video/stream?key=${key}`;
}

function proxyHlsUri(value, baseUrl, headers) {
  try {
    const target = new URL(value, baseUrl);
    return /^https?:$/.test(target.protocol)
      ? registerVideoStream(target.toString(), headers)
      : value;
  } catch { return value; }
}

function rewriteHlsManifest(manifest, baseUrl, headers) {
  return manifest.split(/\r?\n/).map(line => {
    const attrs = line.replace(/URI="([^"]+)"/g,
      (_match,value) => `URI="${proxyHlsUri(value,baseUrl,headers)}"`);
    if (!attrs || attrs.startsWith('#')) return attrs;
    return proxyHlsUri(attrs, baseUrl, headers);
  }).join('\n');
}

app.get('/api/video/stream', async (req, res) => {
  const key = String(req.query.key || '');
  const entry = streamKeys.get(key);
  if (!entry || Date.now()-entry.ts > STREAM_TTL) {
    streamKeys.delete(key);
    return res.status(404).json({ error:'Unknown or expired stream key' });
  }

  const headers = {};
  for (const [name,value] of Object.entries(entry.headers || {})) {
    if (!/^(accept-encoding|host|connection|content-length)$/i.test(name)) headers[name] = value;
  }
  if (req.headers.range && entry.kind !== 'manifest') headers.Range = req.headers.range;

  try {
    const upstream = await fetchSafeUrl(entry.url, {
      headers, signal:AbortSignal.timeout(90_000)
    });
    if (upstream.status >= 400) return res.status(upstream.status).end();

    const pass = { 'accept-ranges':'bytes' };
    for (const name of ['content-type','content-length','content-range','accept-ranges']) {
      const value = upstream.headers.get(name);
      if (value) pass[name] = value;
    }

    if (req.method === 'HEAD') {
      res.writeHead(upstream.status, pass);
      try { await upstream.body?.cancel(); } catch {}
      return res.end();
    }

    const type = upstream.headers.get('content-type') || '';
    if (/mpegurl/i.test(type) || entry.kind === 'manifest' || /\.m3u8(?:$|\?)/i.test(entry.url)) {
      const text = rewriteHlsManifest(await upstream.text(), entry.url, entry.headers || {});
      const data = Buffer.from(text);
      delete pass['content-range'];
      pass['content-type'] = 'application/vnd.apple.mpegurl';
      pass['content-length'] = String(data.length);
      pass['cache-control'] = 'no-store';
      res.writeHead(200, pass);
      return res.end(data);
    }

    res.writeHead(upstream.status, pass);
    const body = Readable.fromWeb(upstream.body);
    body.pipe(res);
    body.on('error', () => { try { res.end(); } catch {} });
    req.on('aborted', () => { try { body.destroy(); } catch {} });
    res.on('close', () => {
      if (!res.writableEnded) try { body.destroy(); } catch {}
    });
  } catch (error) {
    if (!res.headersSent) res.status(502).json({ error:'Upstream fetch failed' });
  }
});
```

`HEAD` 主动取消上游正文；Range 媒体逐请求透传。普通 request `close` 没有销毁动作。HLS 清单的普通 URI 行与 `URI="..."` 属性都先绝对化，再注册同源短期 key。Google 看到的请求始终从解析服务器出口发出。

页面可见时由 canvas 覆盖当前 JPEG；进入 PiP、pagehide 或恢复时立即再发一帧与锚点。`active:false` 是明确终止信号。客户端超过 3.5 秒没更新后，服务器 follower 才接管；失败后退十秒，输出始终通过临时文件加 rename 原子替换。

# 十三个真实踩坑（中）

## 5. request `close` 过早杀死响应流

**症状与根因**：首帧出现后黑屏。上传侧 request 已经 close，下行 response 还没结束，错误监听把上游正文销毁了。


**坏例**

```js
req.on('close', () => body.destroy());
```


**修复**

```js
req.on('aborted', () => body.destroy());
res.on('close', () => {
  if (!res.writableEnded) body.destroy();
});
```


**验证**：三个独立 Range 都完整读完；针对 stream route 的测试明确排除 `req.on('close')`。

## 6. `206 + 1024 bytes` 不能证明媒体可播

**症状与根因**：探针读到第一小块便报成功，真机仍黑屏。它没有覆盖容器索引、后续 Range、音轨与视频轨。


**坏例**

```bash

```


**修复**

```bash
for r in 0-65535 1048576-1114111 4194304-4259839; do

done
ffmpeg -v error -i "$STREAM" -t 8 -map 0:v:0 -map 0:a:0 -f null -
```


**验证**：Pornhub 三段 Range 独立完整返回，前 8 秒音频与视频同时解码。

## 7. iPhone 的每个 Range 都要独立完成

**症状与根因**：第一个区间正常，第二、第三个挂起。代理复用上游流、提前 destroy，或把上一次响应头带到了下一次。


**坏例**

```js
// 改：每个 Range 重新请求上游
const upstream=await fetch(entry.url,{headers:{Range:req.headers.range}});

```


```bash
for r in 0-999999 1000000-1999999 2000000-2999999; do
```

**验证**：上面的三个区间逐个读到 EOF，长度与 `Content-Range` 一致；每次请求都重新 fetch 上游，让该 response 自己走到完成。

## 8. YouTube progressive format 18 实际返回 403

# 十三个真实踩坑（下）

## 10. HLS 只改普通 URI 行，属性 URI 仍漏网

**症状与根因**：分片能播，初始化段、密钥或替代轨道失败。URI 既存在于普通行，也藏在 `URI="..."` 属性中。


**坏例**

```js
if (!line.startsWith('#')) return proxy(line);
```


**修复**

```js
const attrs = line.replace(/URI="([^"]+)"/g,
  (_m, value) => `URI="${proxy(value)}"`);
return !attrs || attrs.startsWith('#') ? attrs : proxy(attrs);
```


**验证**：抽取改写后清单的全部 HTTP 地址；YouTube 样本 39 个 URI 全部变成同源短期代理，前 8 秒音视频双轨可解码。

## 11. 重启后恢复了过期 stream key

**症状与根因**：服务重启后缓存命中，返回的代理 key 已不在新进程内。磁盘错误地保存了临时标识。


**坏例**

```js
save({ publicUrl: '/api/video/stream?key=old' });
```


**修复**

```js
save({ source: { url: upstream, headers: safeHeaders } });
// 启动恢复时重新 registerVideoStream(source.url, source.headers)
```


**验证**：重启进程后，时效内缓存仍命中；返回的新 key 可用且与旧 key 不同。

## 12. 持久缓存误存 Cookie

**症状与根因**：缓存 JSON 带出账号状态。代码把 yt-dlp 返回的全部请求头原样序列化。


**坏例**

```js
entry.headers = info.http_headers;
```


**修复**

```js
const SAFE = /^(user-agent|referer|origin|accept-language)$/i;
entry.headers = Object.fromEntries(
  Object.entries(info.http_headers || {}).filter(([k,v]) => SAFE.test(k) && typeof v === 'string'));
```


**验证**：`grep -Eri 'cookie|authorization|set-cookie' data/` 必须零命中。

## 13. 测试正则范围过宽，旧 bug 假阳性

**症状与根因**：目标 route 已修好，整文件正则仍扫到相邻函数或注释中的 `req.on('close')`。


**坏例**

```js
assert.doesNotMatch(server, /req\.on\("close"/);
```


**修复**

```js
const route = server.slice(
  server.indexOf('app.get("/api/video/stream"'),
  server.indexOf('// POST /api/video/sync'));
assert.match(route, /req\.on\("aborted"/);
assert.match(route, /res\.on\("close"/);
assert.doesNotMatch(route, /req\.on\("close"/);
```


**验证**：旧实现必败、修复实现通过，注释或相邻路由不能改变结果。
