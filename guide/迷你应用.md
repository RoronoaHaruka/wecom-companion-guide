# 迷你应用

> © 2026 Raincove ♡ · Roronoa & Haruka · 文档 [CC BY-NC-SA 4.0](../LICENSE) · 代码 [PolyForm Noncommercial 1.0.0](../LICENSE-CODE)
>
> 把一张自己服务器上的网页挂进企业微信自建应用的主页和底部菜单，让它在个人微信里一按就开，用起来像一个小程序。不需要 ICP 备案的域名，不需要营业执照，不需要小程序账号。

## 先看结论

- 你在个人微信里点开机器人的会话，底部多出一个按钮；按一下，微信自带的浏览器打开你服务器上的一张页面。这张页面可以是任何东西：进程观察窗、状态面板、日志、遥控器。本文把它叫做**迷你应用**。
- 它的本体只是一张静态 HTML 加一组同源的 JSON 接口，全部跑在你现有的机器人服务器上。企业微信只负责三件小事：把这个链接设成应用主页、设成底部菜单、发一张带按钮的卡片。
- 页面用一把**只开这一组接口的钥匙**认证。钥匙随链接走一次，页面存进浏览器本地，再把地址栏擦干净。拿到这把钥匙的人，打不开服务器上任何别的门。
- 底部菜单与卡片在个人微信（微信插件）里已验证可见；应用主页在企业微信客户端里生效。

```text
个人微信 ─ 底部菜单「面板」──┐
个人微信 ─ 卡片「打开」  ───┼─> https://bot.example.com/mini?k=<MINI_APP_TOKEN>
企业微信 ─ 应用主页      ───┘            │
                                          ├─ GET  /mini                静态页面
                                          ├─ GET  /api/mini/status     列表 JSON
                                          └─ GET  /api/mini/stream     SSE 实时流
                                   （只有 /api/mini/* 认这把钥匙，其余路径一律 401）
```

## 为什么不做真正的小程序

微信小程序看起来是更正规的壳，但对个人开发者有两堵墙，都绕不过去：

- 小程序能请求的服务器域名必须完成 **ICP 备案**。海外服务器、海外后缀的域名一律进不了合法域名列表。
- **个人主体**的小程序不能使用 `web-view` 组件，也就是不能把网页套进去；能用 `web-view` 的**企业主体**又需要营业执照。

企业微信自建应用没有这两条限制。应用主页、自定义菜单和卡片消息接受任意 HTTPS 链接，微信插件把它们原样端进个人微信。域名照旧走你在主教程第三步已经配好的那条隧道。

## 结构：三样东西，一把钥匙

| 部件 | 放在哪里 | 作用 |
|---|---|---|
| `mini_app_page.html` | 你的机器人服务器，路径 `/mini` | 页面本身。列表、详情、实时流、按键都在这一个文件里 |
| `/api/mini/status`、`/api/mini/stream` | 同一台服务器，同一个域名 | 页面要读的数据。同源，所以不需要 CORS，`EventSource` 也能直接用 |
| `MINI_APP_TOKEN` | 服务器环境文件（mode 600） | 页面的钥匙。只有以 `/api/mini/` 开头的路径认它 |
| 企业微信配置 | 一次性由脚本写入腾讯侧 | 应用主页、底部菜单、卡片，三处指向同一个链接 |

可运行的参考实现在仓库里：

- [`code/mini_app_server.py`](../code/mini_app_server.py)：标准库写的最小服务器，带钥匙校验、列表接口、SSE 实时流。
- [`code/mini_app_page.html`](../code/mini_app_page.html)：通用页面模板，钥匙引导、列表、详情、实时流、暂停恢复。
- [`code/mini_app_setup.sh`](../code/mini_app_setup.sh)：把链接写进企业微信的三次 API 调用。
- [`tests/test_mini_app.py`](../tests/test_mini_app.py)：钥匙作用域的离线回归测试。

## 钥匙只开一小块

这是整套方案里最值得花心思的一处。链接会被存进腾讯侧的菜单配置和聊天记录里，所以链接里的钥匙必须**只能打开这一组接口**，泄露了也伤不到服务器上别的东西。

规则只有一条：钥匙从 `?auth=` 查询参数或 `Authorization: Bearer` 头里取，用恒定时间比较，并且**只在路径以 `/api/mini/` 开头时才认**。同一把钥匙去敲任何别的路径，一律 401。

Python（标准库，也是参考实现里的写法）：

```python
import hmac

API_PREFIX = "/api/mini/"

def is_scoped_request(path: str, presented: str, expected: str) -> bool:
    """Only paths under API_PREFIX accept the mini-app token."""
    if not expected or not presented:
        return False
    if not path.startswith(API_PREFIX):
        return False
    return hmac.compare_digest(presented.encode("utf-8"), expected.encode("utf-8"))
```

如果你的机器人服务器是 Node/Express，把它接进现有的认证中间件即可：

```js
const crypto = require("crypto");
const MINI_APP_TOKEN = process.env.MINI_APP_TOKEN || "";

function safeEqual(a, b) {
  const x = crypto.createHash("sha256").update(String(a)).digest();
  const y = crypto.createHash("sha256").update(String(b)).digest();
  return crypto.timingSafeEqual(x, y);
}

function miniAppAuth(req, res, next) {
  const presented = (typeof req.query.auth === "string" && req.query.auth) ||
    (req.headers.authorization || "").replace(/^Bearer\s+/i, "");
  const scoped = req.path.startsWith("/api/mini/");
  if (MINI_APP_TOKEN && scoped && safeEqual(presented, MINI_APP_TOKEN)) return next();
  return res.status(401).json({ error: "unauthorized" });
}

app.get("/mini", (req, res) => res.sendFile(path.join(__dirname, "mini_app_page.html")));
app.get("/api/mini/status", miniAppAuth, (req, res) => res.json({ items: loadStatus() }));
```

生成钥匙用 `openssl rand -hex 24`，写进环境文件；想换钥匙就改这一行、重启服务、重跑一遍配置脚本。旧链接立刻失效。

> **如果接口里有会动手的操作**
> 只读的观察页用一把钥匙足够。一旦 `/api/mini/` 下面出现了重启进程、发送按键这类会改变服务器状态的接口，就要意识到：拿到链接的人也能按这些按钮。至少做到危险操作二次确认、日志记录每一次调用；更稳的做法是把动手类接口放到另一把钥匙后面，不写进任何链接。

## 页面怎么拿钥匙

页面第一次打开时链接带着 `?k=<钥匙>`。页面做三件事：

1. 从 `location.search` 里读出 `k`（同时兼容 `#k=`）。
2. 存进 `localStorage`，之后每次请求都从这里取，拼成 `?auth=<钥匙>`。
3. 用 `history.replaceState` 把地址栏擦成干净的 `/mini`。

浏览器里没有钥匙、或者接口回了 401 时，页面显示一个输入框让人手动粘贴。微信自带的浏览器对同一域名的 `localStorage` 是持久的，所以从底部菜单反复打开不需要再次输入；就算被清空，菜单链接本身还带着 `?k=`，重新引导一次即可。

> **用查询参数，不要用井号**
> 微信在打开卡片和菜单链接时可能丢掉 `#` 后面的片段。参考页面两种都认，但写进企业微信的链接一律用 `?k=`。

`EventSource` 不能自定义请求头，所以实时流接口只能靠 `?auth=` 认钥匙；这也是钥匙校验同时接受查询参数和 Bearer 头的原因。

## 接进企业微信：三次调用

下面四段 `curl` 只用占位符。`CORP_ID` 与 `APP_SECRET` 来自主教程第一、二步，`AGENT_ID` 是自建应用的数字 ID，`USER_ID` 是你自己在这家企业里的成员账号，`PAGE_URL` 形如 `https://bot.example.com/mini?k=<MINI_APP_TOKEN>`。仓库里的 `code/mini_app_setup.sh` 把它们串成一条命令。

拿 `access_token`（两小时有效，缓存复用）：

```bash
curl -s "https://qyapi.weixin.qq.com/cgi-bin/gettoken?corpid=${CORP_ID}&corpsecret=${APP_SECRET}"
```

把页面设成应用主页：

```bash
curl -s -X POST "https://qyapi.weixin.qq.com/cgi-bin/agent/set?access_token=${ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d "{\"agentid\": ${AGENT_ID}, \"home_url\": \"${PAGE_URL}\"}"
```

加一个底部菜单，一个 `view` 类型的按钮就够（顶级按钮名称限 16 字节，大约五个汉字）：

```bash
curl -s -X POST "https://qyapi.weixin.qq.com/cgi-bin/menu/create?access_token=${ACCESS_TOKEN}&agentid=${AGENT_ID}" \
  -H "Content-Type: application/json" \
  -d "{\"button\": [{\"type\": \"view\", \"name\": \"面板\", \"url\": \"${PAGE_URL}\"}]}"
```

给自己发一张卡片，点「打开」就是页面：

```bash
curl -s -X POST "https://qyapi.weixin.qq.com/cgi-bin/message/send?access_token=${ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d "{\"touser\": \"${USER_ID}\", \"msgtype\": \"textcard\", \"agentid\": ${AGENT_ID},
       \"textcard\": {\"title\": \"面板\", \"description\": \"点开就是。长按可以收进浮窗。\",
                      \"url\": \"${PAGE_URL}\", \"btntxt\": \"打开\"}}"
```

三次调用都以 `"errcode": 0` 为准。`60020` 是服务器出口 IP 不在企业可信 IP 里，`40014` 或 `42001` 是 token 失效，和主教程第九章的处理方式一样。

## 微信里长什么样

- **底部菜单**：在个人微信里点开这个机器人的会话，输入框左侧多出一个菜单图标，展开就是你配置的按钮。这一处已在个人微信中验证可见，也是日常最顺手的入口。
- **卡片**：出现在会话流里，标题、描述、「打开」按钮。长按卡片打开的页面可以收进微信浮窗，随时拉出来。
- **应用主页**：在企业微信客户端的工作台和应用页里生效。它是否也在微信插件侧展示，本文未做验证，不要依赖它。
- 页面是在微信内置浏览器里打开的普通网页。个别域名首次打开会看到一层「非微信官方网页」的提示，点继续即可；这不影响功能。

## 把它做成自己的

参考实现是教学模板，不是成品。接进你自己的机器人时通常只改四处：

| 要改的地方 | 在哪里 | 说明 |
|---|---|---|
| 数据源 | `mini_app_server.py` 里的 `load_status()` 与 `snapshot()` | 前者返回列表（每项一个 `id`、`name`、`alive`），后者返回某一项的最新快照文本。把示例数据换成你的进程状态、`tmux capture-pane` 输出、日志尾部等 |
| 页面路径与接口前缀 | `PAGE_PATH`、`API_PREFIX`，以及页面里的 `API` 常量 | 三处保持一致。前缀一改，钥匙的作用域也跟着改 |
| 钥匙 | 环境变量 `MINI_APP_TOKEN` | 换钥匙后重跑 `mini_app_setup.sh`，让菜单和主页拿到新链接 |
| 企业微信侧 | `WECOM_AGENT_ID`、`WECOM_TARGET_USER_ID`、`MINI_APP_PAGE_URL` | 写在 `.env.example` 对应的位置，脚本从环境读取 |

页面的样式全部内联，没有任何外部依赖，改颜色、字体、布局直接改那一个文件。想加按钮，就在服务器上多开一个 `/api/mini/` 下的 `POST` 接口，页面里 `fetch` 它；记得回头看一遍上面关于会动手的接口的提醒。

## 常见断点

| 现象 | 原因与解法 |
|---|---|
| 菜单点开是空白页或 404 | `PAGE_PATH` 和链接不一致，或静态文件路径不对。先用桌面浏览器直接打开 `PAGE_URL` 确认页面本身能出来 |
| 页面出来了，列表一直转圈 | 钥匙没进 `localStorage`：链接用了 `#k=` 被微信丢了，改成 `?k=`；或 `MINI_APP_TOKEN` 为空，服务器对所有请求 401 |
| 电脑上正常，微信里 401 | 微信内置浏览器的 `localStorage` 被清过。重新从菜单打开一次（链接自带钥匙）即可 |
| 实时流几秒后断 | 中间的反向代理开了缓冲。给 SSE 响应加 `Cache-Control: no-cache` 与 `X-Accel-Buffering: no`，服务端每十五秒发一条注释行保活 |
| `menu/create` 返回 `40018` 或类似名称错误 | 按钮名称超长。顶级按钮 16 字节以内 |
| `agent/set` 成功但企业微信里主页没变 | 客户端有缓存，稍等或重开客户端 |
| 换了钥匙后菜单打不开 | 只改了环境变量没重跑配置脚本，菜单里还是旧链接 |

## 安全边界

- 钥匙只能开 `/api/mini/`。把这条规则写成测试，`tests/test_mini_app.py` 里就是这么做的：正确钥匙敲别的路径必须失败。
- 服务器绑定 `127.0.0.1`，通过隧道或反向代理对外，和主教程的回调服务一样。
- 钥匙不进日志。参考实现的访问日志只记路径，不记查询串。
- 页面里不要写任何私人信息。它会被微信浏览器缓存，也可能被截图。
- 公开仓库里只提交 `.env.example` 与占位链接。真实的域名、钥匙、企业 ID、应用 ID、成员账号全部留在服务器的环境文件里。
