客服负责「能转发」

微信客服会话进入个人微信的「客服消息」，可以接住文字、文件、图片与合并聊天记录。

应用负责「拿权限」

现有自建应用提供 access_token，并在后台获得指定客服账号的会话管理权。

路由负责「不复制」

两类入口写入同一队列。模型进程保持一份，回信接口由每条消息自己的 source 决定。

01 / Principle

把入口当端口，别把入口当一颗新脑子

渠道只负责收发。上下文、推理与长期会话留在现有 Agent 里。这样多一枚客服账号，只多一条映射，不多一个 tmux。

一枚客服就够。

一一对应只提升微信转发页里的直达感。最小方案用一个统一客服入口，再由服务器把消息路由到既有 Agent。

推荐：统一收件箱

所有转发进入一个客服账号。用固定默认 Agent、最近选择或客服菜单保存路由。

wk_inbox→route table
wm_customer→agent_default

适合什么

个人收件箱、少量用户、入口越少越好的场景。微信里只保留一扇转发门，后台仍可分发到多个 Agent。

进程数量：既有 Agent 数量，不因客服入口增加。

可选：名字直接选模型

每个客服账号固定映射到一枚现有 Agent。转发时在微信「客服消息」中直接选择目标名称。

wk_alpha→agent_alpha
wk_beta→agent_beta

仍然不增 tmux

这些 Agent 本来已经常驻时，每个客服只绑定到对应 Agent 已有的消息队列。应用入口和客服入口共用该 Agent 的长进程、记忆与交接。

进程数量：仍是既有 Agent 数量。

02 / Setup

后台只做一次，服务器从此常驻

微信客服有两层授权。能列出账号，只证明第一层成功；`sync_msg` 返回零，才说明会话读取权真正接通。

创建客服账号

进入 应用管理 → 微信客服 → 客服账号，设置名称与头像。取得客服入口链接，让个人微信打开一次，会话会留在「客服消息」里。

选择可调用接口的应用

进入微信客服的 API 页面，在「可调用接口的应用」中选择一个现有自建应用。这个应用的 Secret 将用于获取 access_token。

分配会话管理权

在「企业内部开发」或「通过 API 管理会话消息」中，把客服账号明确分配给该应用。随后用该应用 token 调用 `kf/sync_msg`，以 `errcode == 0` 验证。

配置事件回调

填写 HTTPS URL、Token 与 EncodingAESKey。`kf_msg_or_event` 只负责唤醒；真实消息继续由 `sync_msg` 拉取。公开最小桥接器只实现持久 cursor 轮询，默认 15 秒；需要更高频率时再接入回调 token。

把客服映射到已有队列

保存 `open_kfid → existing_agent`。应用回调与客服同步统一转换成 route envelope，写入同一个队列，禁止为客服再启动一份 Agent。

03 / Protocol

回调说「有消息」，cursor 决定「从哪里接着读」

微信客服消息最近约三天可取。持久化 cursor、按 msgid 幂等、媒体立刻下载，是这条链路稳定的三个支点。

字段作用实现要求
next_cursor下一页与下次增量读取起点每页处理成功后原子保存；服务重启继续使用
has_more当前是否还有下一页以它终止分页，不能用空 msg_list 判断
msgid消息唯一键数据库 UNIQUE；允许重复拉取，禁止重复消费
origin3=客户，4=系统，5=接待人员Agent 输入通常只接 origin=3
open_kfid哪一枚客服账号映射到现有 Agent；未知 ID 直接忽略
external_userid微信客户身份个人收件箱可在首次消息后锁定该 ID

合并转发会展开成 `merged_msg`

每一条子消息都有发送者、时间、类型与二次编码的 JSON。`msg_content` 需要再解析一遍；其中的 media_id 要在过期前换成本地文件。

真实边界

某些联系人名片只会变成 `[暂不支持的消息]`，服务端无法恢复已被微信裁掉的字段。客服账号也不能作为普通群成员加入微信群。

06 / Diagnose

七个最常见的断点

先看权限层，再看 cursor 与发送窗口。不要用高频盲测制造新的 45009。

48002

应用未获微信客服接口或会话管理权限。

检查「可调用接口的应用」和「企业内部开发」两层授权。

48007

应用能看到客服体系，无权管理该客服账号。

把对应客服账号明确分配给当前自建应用。

45009

短时请求过多。

停掉密集探测，缓存 access_token，使用回调 token，降低轮询频率。

95001 / 95002

分别为超过五条累计额度、超过48小时回复窗口。

等待客户再次发消息；发送前按 UTF-8 字节预计算总分片。

95033

自定义客服消息msgid重复。

同一重试复用原msgid；不要换新ID再发一遍。

EMPTY PAGE

`msg_list` 为空，但可能仍有下一页。

始终读取 `has_more`，并保存服务端返回的 `next_cursor`。

UNSUPPORTED

收到 `[暂不支持的消息]`。

该卡片结构已在微信侧被裁掉，改用链接、图片、文件或合并聊天记录。

07 / Boundary

公开代码，收紧边界

客服入口面对真实微信消息。桥接器越小越好，认证、授权、幂等与文件权限一处都不能省。

锁定身份

个人收件箱可在第一条合法消息后绑定 external_userid。未知客户、未知 open_kfid 直接忽略。

验签解密

回调校验签名、CorpID 与 AES 填充。优先使用成熟实现，避免自行拼密码学协议。

秘密不落日志

Secret、Token、EncodingAESKey 与 access_token 放环境变量或 600 文件；错误输出只保留 errcode。

消息原子落地

队列先写临时文件再 rename。原始 JSON、媒体、待发回复与 state 目录 700，文件 600；媒体下载另设字节上限。

授权目标集合

发送工具只接受当前应用成员 ID 与已绑定客服客户 ID。不要允许模型自由构造目标。

公开仓库脱敏

只提交 `.env.example`。截图、测试夹具与 README 全部使用 ww_example、wk_example、wm_example。
