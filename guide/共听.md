# 共听：把一台音乐播放器挂进微信，让 Agent 陪你听歌

> © 2026 Raincove ♡ · Roronoa & Haruka · 文档 [CC BY-NC-SA 4.0](../LICENSE) · 代码 [PolyForm Noncommercial 1.0.0](../LICENSE-CODE)
>
> 聊天窗口里的 Agent 不止会说话。这一篇把一台完整的网页音乐播放器接进企业微信底部菜单，Agent 能在聊天里丢出一张「歌卡」，你一点开歌就在放；它也知道你此刻正在听什么，接话自然得像坐在旁边。前端是一个零依赖单文件，本仓附完整参考实现；后端只发接口契约，自己搭。

## 先看结论

- 形态复用 v1.2.0 迷你应用的路子：网页挂在**企业微信底部菜单**，微信插件把菜单原样端进个人微信，点开像小程序。
- 前端是一个**零构建、零依赖的单文件** [`code/co_listen_page.html`](../code/co_listen_page.html)：六个页签（歌单/搜索/云歌单/FM/日推/播客）、全屏播放器（队列、留言、±15 秒、译文/罗马音歌词）、迷你条、断点续播。
- 音源走你自己的**后端代理**连网易云音乐 API，页面只认一份接口契约（见下文表格），换别的音源只要照契约实现。
- **共听**由三件小东西组成：Agent 发的**歌卡深链**（点开即播、客歌插队放完归还）、页面的 **now-playing 上报**、bot 侧把「正在听什么」**注入模型上下文**。三件各自都很小，合起来就是「它在陪你听」。
- 微信 WebView 有一串著名的坑（声道被抢、双页互掐、键盘顶歪视口、后台切歌被拦），参考实现里每个都带解法，附录有完整清单。

## 00 · 架构总览

```text
个人微信 ─ 底部菜单「听歌」──┐
个人微信 ─ Agent 发的歌卡 ────┼─> https://bot.example.com/music?auth=<key>
企业微信 ─ 应用主页 ─────────┘        │
                                      ├─ /music                     单文件页面
                                      ├─ /api/music/*               后端代理（自建）
                                      │        └─> 网易云音乐 API（登录态 Cookie）
                                      └─ POST /api/music/now-playing
                                               └─> now-playing 状态 ─> bot 注入模型上下文
```

页面与接口同源，不需要 CORS；访问用一把钥匙（首次输入后存 localStorage，也可以用 `?k=` 带入，页面会立刻把它从地址栏洗掉）。菜单配置方法与 v1.2.0 迷你应用一章相同，把 URL 换成音乐页即可。

## 01 · 后端接口契约

参考实现页面只调用下面这些接口。**本仓不含后端实现**：`stream`、`search`、`lyric` 这些本质是网易云 API 的转发与整形，照契约把你自己的代理层写出来即可（下一节讲音源怎么接）。所有接口都带 `?auth=<key>` 鉴权，401/403 时页面会弹钥匙门。

| 接口 | 方法 | 说明 | 返回 |
| --- | --- | --- | --- |
| `/api/music/playlist` | GET | 自建收藏歌单 | `[{id,name,artists,album,albumPic,duration}]` |
| `/api/music/playlist` | POST | 收藏一首（body 为歌对象） | — |
| `/api/music/playlist/:id` | DELETE | 取消收藏 | — |
| `/api/music/search?q=&limit=` | GET | 搜索 | `{songs:[歌对象]}` |
| `/api/music/stream/:id` | GET | 音频流（支持 Range，浏览器 `<audio>` 直接吃） | 音频 |
| `/api/music/lyric/:id` | GET | 歌词三轨 | `{lrc,tlyric,romalrc}` |
| `/api/music/fm` | GET | 私人 FM 一批歌 | `{songs:[...]}` |
| `/api/music/daily-rec` | GET | 每日推荐（可由 Agent 生成，`reason` 是推荐语） | `{date,note,songs:[{…,reason}]}` |
| `/api/music/user-playlists` | GET | 登录账号的云歌单列表 | `{playlists:[{id,name,coverUrl,trackCount,isOwner,creator}]}` |
| `/api/music/playlist-detail/:pid` | GET | 某个云歌单整单 | `{songs:[...]}` |
| `/api/music/dj/sublist` · `/dj/hot` | GET | 订阅/热门播客电台 | `{radios:[{id,name,picUrl,dj,programCount}]}` |
| `/api/music/dj/programs/:rid?limit=` | GET | 电台节目单 | `{programs:[{mainSongId,name,radioName,coverUrl,duration,serialNum}]}` |
| `/api/music/comments/:songId` | GET/POST | 这首歌下的私有留言（不是公网评论） | `[{id,author,text,timestamp,songTimestamp}]` |
| `/api/music/comments/:songId/:cid` | DELETE | 删一条留言 | — |
| `/api/music/stats` | GET | 听歌统计 | `{totalPlays,uniqueSongs,totalDuration,hourDistribution[24],top[]}` |
| `/api/music/now-playing` | POST | 播放状态上报（共听的地基，见 04） | — |

歌对象统一为 `{id,name,artists,album,albumPic,duration}`，`duration` 毫秒。页面对缺字段宽容：封面缺了会用歌名搜回来补。

## 02 · 音源：网易云 API、扫码登录与登录态保存

**代理层怎么搭**：现成路子是自建一个 NeteaseCloudMusicApi 类的开源服务（社区有多个维护中的同类项目，选一个活跃的），你的后端拿它当上游；也可以直接在自己后端里封装官方 web 端点。两种都把登录态 Cookie 揣在服务端，页面永远只见你的 `/api/music/*`，不见上游。

**扫码登录三步**（NeteaseCloudMusicApi 类服务的标准流程）：

1. `GET /login/qr/key` 拿一次性 `key`；
2. `GET /login/qr/create?key=<key>&qrimg=true` 拿二维码图，展示给手机扫；
3. 轮询 `GET /login/qr/check?key=<key>`：`801` 等待扫码、`802` 已扫待确认、`803` 登录成功——成功那次的响应里带完整 Cookie。

**登录态怎么存**：Cookie 里真正值钱的是 `MUSIC_U`。把整串 Cookie 存进服务器上的环境文件或 mode-600 的独立文件，进 `.gitignore`，别写进代码；`.env.example` 里只放占位符（如 `NETEASE_COOKIE=`）。后端每次调上游时带上它。

**登录态会过期**：过期后匿名接口（搜索、歌词、多数播放）照常，需要身份的接口先倒——典型现象是云歌单、播客订阅这些页签开始报 401 或空数据，而搜索还好好的。此时重跑一遍扫码流程换新 Cookie 即可；页面对 401 的文案就是「登录态过期了，需要重新扫码登录」。若想省心，可以在后端加个每日自检：拿登录态调一次 `/login/status` 类端点，失效就通知你重登。

**灰色歌曲**：无版权/会员专享的歌，上游拿不到音频流。页面的策略是报错先重连一次（网络毛刺很常见），再失败就提示「可能是灰的」，不无限重试。

## 03 · 歌卡：Agent 把歌丢进聊天

Agent 在聊天里发一张卡片（v1.2.0 讲过的 `news`/`textcard` 都行），跳转链接长这样：

```text
https://bot.example.com/music?sid=<歌ID>&sname=<歌名>&sartist=<歌手>
```

点开落地即全屏播放器，歌已装好开始放（iOS 首次需要一下手势，页面会把大播放键亮着等）。左上角是「‹ 返回」，一按回音乐主界面。

两条实战规矩：

- **链接必须干净**。参数只放歌 ID 和纯文本的歌名歌手，**不要**把封面图地址这类「URL 套 URL」的东西编码进参数——嵌套编码的长链接长得像钓鱼跳转，微信安检很乐意给它盖「已停止访问该网页」的红章，而且封杀的是整条链接。封面让页面自己拿歌名搜回来补，卡片链接保持素净。
- **客歌插队，放完归还**。用户自己可能正听着一个 120 首的队列。歌卡进门不清场：参考实现把这首歌插进已保存队列的当前位置，放完自动接回用户原来那首、原来那一秒（`deepLink()` 里 `resumeSeekOnce` 那几行）。Agent 送的歌是客人，唱完一首就退，主人的场子原样还回去。

## 04 · 共听的另一半：让模型知道「正在听什么」

到这里 Agent 能把歌送过去了；共听的另一半是反向的——模型接得住「我在听歌」这个话头。配方是三段，全部通用：

**① 页面上报**。参考实现在播放、暂停以及播放中每 15 秒定时，各 `POST /api/music/now-playing` 一次：

```json
{
  "songName": "...", "artist": "...", "album": "...",
  "progress": 83.2, "duration": 262.0,
  "source": "web", "songId": "...",
  "isPlaying": true, "action": "pause 时为 'pause'"
}
```

**② 后端维护一份 now-playing 状态**。一个小 JSON 就够：最后一次上报的内容加 `updatedAt` 时间戳。多个来源（网页、App）就让 `source` 字段说明来自哪里，后端保留最新一条。

**③ bot 侧每轮注入一行**。你的 bot 在把用户消息交给模型之前，读一下这份状态，往上下文里加一行系统侧文本，例如：

```text
[用户此刻正在听《歌名》（歌手），来自网页播放器；数据 12 秒前更新]
```

三条纪律，比实现本身重要：

- **新鲜度是生命线**。注入前算 `freshSec = now - updatedAt`，超过阈值（比如几分钟）的数据**不得**当「此刻」注入——要么不注入，要么明确写成「几分钟前在听」。拿旧数据冒充现在，模型会一本正经聊一首早就停了的歌，比不知道更糟。
- **无数据就是无数据**。状态为空就一个字都不注入，绝不编造。
- **注入是背景不是指令**。提示模型这是环境信息，自然的时候可以接一句（「这首循环第三遍了？」），不必每条都郑重其事地播报——那会很吵。

暂停也上报（`action:'pause'`），bot 才知道歌停了。这一小节到此为止就是完整的共听；再往深处的多源感知属于你自己的系统设计，不在本篇范围。

## 05 · 歌词同步的原理

`/api/music/lyric/:id` 返回三轨 LRC：`lrc` 原文、`tlyric` 译文、`romalrc` 罗马音（后两轨没有就是空）。参考实现的做法：

1. **解析**：逐行抓 `[mm:ss.xx]` 时间标签（一行可以有多个标签，正文重复挂到每个时间点），三轨喂进同一张以时间为键的表，得到按时间排序的 `{t, zh, tr, ro}` 数组；
2. **定位**：`<audio>` 的 `timeupdate` 事件里拿 `currentTime`（加约 0.3 秒的提前量，人耳觉得「正好」），二分或线性找当前行；
3. **渲染**：当前行加高亮类、`scrollIntoView({block:'center'})` 平滑滚到中间；译文和罗马音各自一个开关，存 localStorage。

整段逻辑在参考实现的 `parseLrc` / `syncLyric` / `renderLyrics` 三个函数里，不到七十行，没有任何依赖。

## 06 · 断点续播与队列记忆

页面把队列（裁到 120 首的瘦身版）、当前下标、播放位置连同时间戳存 localStorage（`pagehide` 和每 4 秒节流各存一次）。下次打开：48 小时内的状态直接还原——列表在、封面在、进度条停在离开那一秒，第一下点播放从那一秒继续。歌卡深链进来时也是先读这份状态再插队，所以「放完归还」能精确到秒。

## 07 · 附录：微信 WebView 踩坑清单

全部在参考实现里有对应代码，搜注释即可。

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| 自动播放拦截 | 没有用户手势的第一声 `play()` 被拒 | 深链进门先试 `play()`，被拒就亮着大播放键等那一下手势 |
| 后台/浮窗切歌被拦 | 歌放完，下一首无声 | `ended` 事件栈里**同步**调 `play()`；被拒走 `WeixinJSBridge.invoke('getNetworkType',{},cb)` 里再试；还不行就挂起，`visibilitychange` 回前台立刻续上 |
| 声道被抢空转 | 微信语音/通知一响，进度条走但没声 | 回前台把 `currentTime` 回拨 0.01 秒轻踢一脚重抓声道 |
| 双页互掐 | 浮窗挂一页、菜单又开一页，互抢声道 | localStorage 写一个带时间戳的「谁在出声」锁，3 秒巡一次，不是自己就暂停让位 |
| 播放冻结 | 流断了，元素既不报错也不前进 | 看门狗 4 秒一查 `currentTime`，播起来之后（>2s）连续三次不动就原地重载、seek 回原位续播 |
| 键盘顶歪视口 | 键盘收起后整页向上错位：顶部被裁掉，底下露出后面的内容 | `focusout` 与 `visualViewport` 高度回涨时 `scrollBy(0,1)` 再 `scrollBy(0,-1)` 把视口拽回 |
| 长链接被安检拦 | 卡片链接打开是「已停止访问该网页」 | 见 03：参数干净化，不带嵌套编码的 URL |
